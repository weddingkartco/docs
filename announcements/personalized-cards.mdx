---
title: "Personalized cards"
description: Print each guest's name, or any guest detail, on your invite PDF or image — on as many pages as you like
---

A personalized card is your own invite (a PDF or a static image) with text printed on it for each guest — "Dear Hemendra Shah ji & family" on the cover, the same name again on page 2, "Your table · 7" on the reception page. Every guest receives their own copy on WhatsApp.

You can place up to **10 text blocks** on a card, on any page, and each block can use the guest's name or **any guest detail** from your guest list (Guest Alias, Table No, Hotel Name, Room Number, Relation, or any column you imported).

<Note>
Personalized cards cost **1 extra credit per number messaged**, however many text blocks or pages you use. See [What it costs](/announcements/overview#what-it-costs).
</Note>

## Before you start

- Attach your invite to the announcement as a **PDF or a static image**. Personalization is only available for PDFs and static images — if you attach anything else you'll see *"Personalization is only available for PDFs and static images."*
- After you upload, Weddingkart prepares the pages. You'll see *"Processing the card… this usually takes a few seconds."* If it fails you'll see *"We could not process this card. Try re-uploading a cleaner PDF."*
- If you want to print a detail other than the name (for example a nickname), make sure that column was **imported as a guest detail** when you uploaded your guest list. Details you didn't import can't be printed.

## Add text to your card

<Steps>
  <Step title="Open Personalize invite">
    From the announcement, open **Personalize invite** and choose **Write on card**.
  </Step>
  <Step title="Add your first block">
    On a new card, tap **Add Guest Name on page 1**. A block with the guest's name appears in the middle of the page and the editor opens. If this card was already personalized before, your existing setup opens as **Block 1** — nothing about it changes until you edit it.
  </Step>
  <Step title="Write the text">
    In the **Text** tab, type the words you want and tap a detail chip to insert it — for example type `Dear `, tap **Guest Name**, then type ` & family`. Inserted details appear as grey pills; one backspace removes a whole pill. The chips are the same ones you see when writing announcements, and each shows how many guests have that detail (for example **5/8**). A chip marked **no data yet** can still be inserted.
  </Step>
  <Step title="Style and place it">
    In the **Style** tab choose the font, size, bold/italic, colour (tap **Pick from card** to match a colour on your invite, or type a hex code) and alignment. Place the block with **Top / Centre / Bottom** or the arrow buttons, or drag it on the preview to fine-tune.
  </Step>
  <Step title="Add more blocks">
    Tap **Add on page N** for another block on the page you're viewing, or open a block and use **Copy to page** to repeat it on another page — the editor jumps to that page with the copy selected and shows *"Copied to page 2. Check the position."*
  </Step>
  <Step title="Check and save">
    Review **Before sending** (below), then save. You'll see *"Personalization saved"*.
  </Step>
</Steps>

On a phone, tapping a block opens its editor in a panel over the card so you can still see the preview. On a tablet or computer the editor appears beside the card.

### Putting the name on two pages

This is the most common request. Open the name block, tap **Copy to page**, pick the page, then adjust the position. Both pages print the same guest's name.

### Two lines of text

Each block is one line (*"One line per block. Add another block for a second line."*). For "Shri & Smt Hemendra Shah" with "& Family" underneath, use two blocks one above the other.

## Using a detail other than the name

Any detail from your guest list can go in a block — tap its chip. For example `Dear {Guest Alias} & family` prints each guest's nickname.

**When some guests don't have that detail**, the **Before sending** check tells you how many are missing it and offers **Use Guest Name when missing**. After you tap it, the pill reads **Guest Alias → Guest Name**: guests with an alias get the alias, everyone else gets their name.

You can instead set **backup text** for a detail ("Backup text when Table No is missing"). Backup text belongs to the detail, not the block, so it applies to every block that uses that detail — the check shows which blocks ("Used by blocks 1 and 3").

Values like `NA`, `N/A`, `-`, `nan`, `none` and `null` in your guest list count as **missing**, so they are never printed on a card. The number `0` counts as a real value.

## Before sending

The **Before sending** section checks every guest on the card and shows, for example, *"236 of 248 guests ready"*. It lists:

- **Details that are missing** for some guests, with **Use Guest Name when missing** and a backup-text box.
- **Guests who can't get a personalized card**, with the reason:
  - *No Guest Alias* (or whichever detail is missing, with no backup)
  - *No guest name*
  - *Name uses a script the card fonts can't print*
  - *Card too large to personalize*
- **Text that shrinks a lot** — long names shrink automatically to fit (*"Long text shrinks to fit"*); if a guest's text becomes very small you'll see which block and page, with a button to preview that guest.
- **Details that don't exist**, for example after a column was deleted: *"Block 2 uses a field that doesn't exist. Fix it before saving."* You can't save until this is fixed.

Use **Preview as guest** to see any guest's card, and **Worst cases** (*"Show the guests most likely to look wrong"*) to jump straight to the longest name, a guest missing a detail, and a guest who got the backup.

### Guests who can't get a personalized card

If some guests can't be personalized, saving asks what to do: *"12 guests can't get a personalized card"*.

- **Send them the plain card** — they get your invite without printed text. They are charged the normal message rate but **not** the personalization credit.
- **Exclude them** — they are left out of this send and **not charged**.
- **Fix** — go back and add backup text, **Use Guest Name when missing**, or fix the guest list.

If every guest is blocked, the send doesn't go out and nothing is charged.

## Supported languages

Names in English (Latin script), **Gujarati** and **Devanagari** (Hindi, Marathi) print correctly, including names that mix scripts. If a guest's name uses a script the card fonts can't print, that guest is listed under *"Name uses a script the card fonts can't print"* instead of receiving a card with empty boxes.

## Limits

| Limit | Value |
|---|---|
| Text blocks per card | 10 (*"Up to 10 text blocks"*) |
| Characters per block | 200 |
| Lines per block | 1 (stack blocks for more lines) |
| File types | PDF, static images |

## When two people edit the same card

If someone else saves the card while you're editing, saving shows *"Someone else edited this card. Reload to see their version."* Reload, then make your change again.

While an announcement using the card is sending, you can't change the card — wait until the send finishes.

If you're on an older version of the app and the card has more than one text block, you'll see *"This card has more than one text block. Update the app to edit it."*

## Common questions

<AccordionGroup>
  <Accordion title="Does each extra text block or page cost more?">
    No. It's 1 extra credit per number messaged for a personalized card, whether it has one block or ten, on one page or many.
  </Accordion>
  <Accordion title="Can I print the name on page 1 and page 2?">
    Yes. Open the name block, tap **Copy to page**, choose page 2 and adjust the position.
  </Accordion>
  <Accordion title="Can I print a nickname instead of the formal name?">
    Yes, if your guest list has a nickname column imported as a guest detail (for example **Guest Alias**). Insert that chip, then tap **Use Guest Name when missing** so guests without a nickname still get their name.
  </Accordion>
  <Accordion title="A guest's card says something wrong. What happened?">
    The card prints exactly what's in your guest list for that guest. Use **Preview as guest** to check them, fix the value in the guest list, and send again.
  </Accordion>
  <Accordion title="Why is a guest missing from the send?">
    If you chose **Exclude them**, guests who couldn't be personalized were left out. The **Before sending** list shows who and why. Fix their details or choose **Send them the plain card** instead.
  </Accordion>
  <Accordion title="Can a block have two lines?">
    No — each block is a single line. Add a second block directly underneath.
  </Accordion>
  <Accordion title="Can I use Hindi names?">
    Yes. Devanagari names (Hindi, Marathi) and Gujarati names print correctly.
  </Accordion>
</AccordionGroup>
